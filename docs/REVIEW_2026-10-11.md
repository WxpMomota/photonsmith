## Open: repository

1. **CI skips the Scene Builder render tests.** `findLauncher()` (six copies in `tests/unit/scene_*_tests.cpp` and `scene_builder_tests.cpp`) looks for `ray_tracer(.exe)` in the working directory, `../` and `../../`; the CI jobs build only `unit_tests` and `cpu_integrator_tests` and run from the repository root, so 15 render tests report SKIPPED on both platforms (they pass with a symlink to the launcher). Fix: build the `ray_tracer` target in CI, honour an `RT_LAUNCHER` environment variable, and move the copies of `findLauncher` into `agreement_test_helpers.h`.
2. **Metal ctests CI never runs**: `metal_poc_alpha_cutout`, `cloud_furnace`, `subsurface`, `nanovdb`, `media_lights`, `clipped_medium`, `subsurface_sky`, `consistency`, `prepare_gpu`, `sppm_gpu_falls_back` (the filter in `.github/workflows/unit-tests.yml` names the older ones). They guard the newest Metal claims.
3. **52 test files are MSBuild-only** (`tests/portable_build_exclusions.txt`), mostly through a transitive `optix_types.h`; about ten are pure maths and would run on the Mac with an `optix.h` stub.
4. **Licences of `models/`**: 22 meshes (about 66 MB) in an MIT repository; `THIRD_PARTY_NOTICES.md` and `docs/MODELS.md` say the per-model table was not checked file by file, and some sources are non-commercial or research-only. The GUI downloads them from `raw.githubusercontent.com` pinned to commit 4359b5d, so a history purge would break that. Record a verified licence per model, or move the unclear ones to the pack downloader.
5. **Two headers named `camera_path.h`** (`launcher/` and `src/TheRestOfYourLife/`); only the second is included by bare name today.
6. **The code-size baseline is raised by hand inside feature commits** (`mapPbrtMaterial` 315 to 336, `applyTheme` 777 to 795, `camera_render` 556 to 582, and others), and each function may grow by max(5%, 20 lines) before the check fails. Near the file limit: `qt_gui/mainwindow.h` 1911, `metal_poc_sampling.metal` 1886, `pbrt_gpu_builder.h` 1841.
7. Smaller: the reflectance-to-conductor-k formula still exists three times (`GPU_SCENE_COMMON.md` lists the Metal half as pending); test counts differ between README ("over 5,000"), the CI comment ("about 3,570") and the Mac run (3,943); `git gc` is due (40 MB of loose objects).

## The Scene Builder findings (for the Windows session): handled

*Update: the Windows session took these on in commits `a132eae` and `ce4e08e` ("Fix the findings of a review of the Scene Builder work", "Scene Builder: fixes from the Mac session's review"): the portrait field of view, the saved view's sensor width, the rendered viewport's depth of field and the texture-repeat rules among them. Their commit messages say which; the list below is the original report, kept so each item can be checked against them.*

Reported by the review of the Windows-side commits; "confirmed" says the reviewer ran it, otherwise it was read.

1. **fov is treated as vertical, pbrt takes it on the shorter image side** (`scene_pbrt_writer.h:273` writes `Camera.fov` unchanged; the loader converts when width < height, `pbrt_flatten_scene_parts.h:611`). The rendered viewport sets `fov` at the widget's own shape (`scene_builder_rendered.cpp:184`), so a portrait picture is framed about 1.3x wider than the overlays; the focal-length maths in `scene_camera_lens.h` has the same flaw for portrait pictures (the tests use landscape only).
2. **The rendered viewport's depth of field is half strength and never updates**: `scene_builder_rendered.cpp:207` passes `lensRadius` where the API takes a diameter (`cpu_interface.cpp:527` halves it), and `sceneSignature`/`classify` ignore the lens, so changing the f-number or Pick focus does nothing until an unrelated restart.
3. **Scaling a Terrain breaks it** (confirmed): `scene_array.h:100` `scaleObject` multiplies `radius` (roughness, 0 to 1) and `radius2` (hills); a default Terrain scaled by 3 has roughness 1.5, a validate error that blocks rendering.
4. **A saved view's sensor width flips to the scene camera's on a JSON round trip** (confirmed): `scene_json.h:310` writes `sensorWidthMm` only when it is not 36, and views are read starting from the scene camera, so undo/redo and save/load change a view saved at 36 mm once the scene sensor is 24 mm.
5. **Applying "Sunny day" or "Golden hour" twice gives a flat white sky with no Sun**: `edit()` (`scene_builder_widget.cpp:428`) calls `syncSunAndSky` only when the sky signature changes.
6. **Zero texture repeats is an error even with no texture** (confirmed): `scene_validate.h:145-148`; the rows are hidden without a picture, so the field to fix is not visible.
7. **Texture shift is not "of a repeat"**: the writer uses `(u - off) * scale` (`scene_pbrt_writer.h:80`), the `scene_model.h:60` comment says a repeat; repeats 4 with shift 0.25 moves by one whole repeat.
8. **A Terrain's Seed edit does not redraw the 3D view**: `geometrySignature` (`scene_3d_view.cpp:368-383`) does not mix in `seed`.
9. **The Height/Normal choice does not control the renderer**: `pbrt_cpu_builder.h:150-190` decides by pixel content, so a colour picture chosen as "Height map" renders as a normal map.
10. **The rendered viewport can block the UI thread and spin**: every tick with an edit runs a full `toPbrt` three times (128-cell Terrain: about 210 ms per tick; 300 objects with 100 tori: about 0.8 s); if `startViewportSession` fails, it retries every 60 ms with a disk write; turning Orthographic on after the start leaves the render perspective.
11. Smaller: `pathShown()` ignores through-camera and preview mode, so the hidden camera-path markers can still be dragged; a Cyclorama with radius 0 shares floor normals with the wall; `applyMaterialPreset` keeps the bump file but resets its texture repeats; Drop to floor moves locked and hidden items; `translationOnly` restarts for any scene with a volume.

Also noted: OptiX's new outward subsurface probe normals are untested for subsurface on open sheets.
